## الملخص التنفيذي

**التقييم العام: 5.5 / 10** — مشروع طموح ومنجز وظيفياً بشكل مثير للإعجاب لمشروع شخصي، لكنه **ليس جاهزاً للإنتاج** بسبب تسريب أسرار في Git، وغياب ضوابط أمنية أساسية، ونمو غير محدود لقاعدة البيانات، وتكرار بنيوي في طبقة الجامعين.

**أكبر نقاط القوة:**
- بنية معيارية واضحة (collectors / api / models / middleware) يسهل التنقل فيها.
- استثمار حقيقي في الأداء: ETag + Cache-Control، تحميل كسول لـ Three.js، تقسيم الحزم يدوياً، Service Worker.
- وعي أمني جزئي: تهريب HTML في نوافذ الخريطة (`esc`/`safeUrl` في `RasadMap.jsx`) مكتوب بعناية.
- اختبارات + CI موجودة فعلاً (نادر في مشاريع بهذا الحجم).
- دعم ثنائي اللغة RTL/LTR ومسارات نشر متعددة (Docker / Pages / مثبّت ويندوز).

**أخطر نقاط الضعف:**
1. 🔴 مفاتيح API حقيقية مرفوعة في Git (ملف `.env`) — يجب إبطالها فوراً.
2. 🔴 قاعدة البيانات تنمو بلا حدود (لا توجد أي سياسة احتفاظ/تنظيف).
3. 🔴 `/api/refresh` و`/api/flights/live` بلا مصادقة ويطلقان عمليات مكلفة خارجية عند كل طلب.
4. 🟠 روابط غير مُعقّمة في `NewsFeed` و`IranPanel` (ثغرة XSS عبر `javascript:` URI من خلاصات خارجية).
5. 🟠 healthcheck في Docker مكسور، و`npm run lint` مكسور، وترقيم الإصدارات متضارب (1.0 / 1.4 / 1.5).

**أول 5 أشياء يجب إصلاحها (بالترتيب):** انظر [المرحلة الأولى](#المرحلة-الأولى--إصلاحات-حرجة-أيام).

## 1. النتائج الحرجة (أمن)

### 🔴 SEC-1: أسرار حقيقية مرفوعة في المستودع وتاريخ Git

- **المكان:** `.env` في جذر المستودع (commit `271d6e2` "Create .env").
- **المشكلة:** الملف يحتوي مفتاح NewsAPI حقيقياً (`newsapi_key=2f4ea2…`) وبيانات اعتماد OpenSky كاملة (`OPENSKY_CLIENT_SECRET=Frpy…`). وجود `.env` في `.gitignore` لا يفيد لأن الملف تُتبِّع **قبل** إضافته للتجاهل.
- **لماذا هي مشكلة:** أي شخص يستنسخ المستودع (أو يتصفح تاريخه حتى بعد حذف الملف) يحصل على المفاتيح. حصة NewsAPI المجانية قابلة للاستنزاف، وحساب OpenSky قابل للاختطاف.
- **التأثير:** تسريب اعتمادات + احتمال حظر الحسابات + إذا أصبح المستودع عاماً فالتسريب فوري وشامل.
- **الحل:**
  1. **أبطل المفاتيح فوراً** من لوحتي NewsAPI وOpenSky وأصدر بدائل.
  2. أزل الملف من التتبع: `git rm --cached .env`.
  3. نظّف التاريخ: `git filter-repo --path .env --invert-paths` (أو BFG) ثم force-push، أو الأسهل عملياً: اعتبر التاريخ محروقاً وأبطل المفاتيح فقط.
  4. أضف `.env.example` بقيم وهمية موثّقة:
     ```bash
     # .env.example
     newsapi_key=YOUR_NEWSAPI_KEY_HERE
     OPENSKY_CLIENT_ID=
     OPENSKY_CLIENT_SECRET=
     DATABASE_URL=sqlite+aiosqlite:///./rasad.db
     ```
  5. فعّل GitHub Secret Scanning + Push Protection من إعدادات المستودع.

### 🔴 SEC-2: `/api/refresh` بلا مصادقة أو تحديد معدل

- **المكان:** `backend/app/main.py:120`.
- **المشكلة:** نقطة `POST /api/refresh` تُطلق جمعاً كاملاً من 5 مصادر خارجية (عشرات طلبات HTTP + كتابات DB) لأي طالب، مع CORS مفتوح (`allow_origins=["*"]`) وربط الخادم بـ `0.0.0.0`.
- **لماذا هي مشكلة:** أي صفحة ويب يزورها المستخدم تستطيع قصف الخادم بطلبات refresh (استنزاف حصص NewsAPI/GDELT وحظر IP من مزودي الخلاصات)، وأي جهاز على الشبكة المحلية يصل للخادم مباشرة.
- **الحل:** أضف throttle خادمياً (رفض إن جرى جمع خلال آخر N ثانية) كحد أدنى:
  ```python
  _last_refresh: float = 0.0
  REFRESH_COOLDOWN = 120

  @app.post("/api/refresh")
  async def manual_refresh():
      global _last_refresh
      if time.time() - _last_refresh < REFRESH_COOLDOWN:
          raise HTTPException(429, "Refresh throttled — try again later")
      _last_refresh = time.time()
      ...
  ```
  وفي وضع سطح المكتب اربط الخادم بـ `127.0.0.1` بدل `0.0.0.0` (تم في `run_desktop.py` ✅ لكن وضع التطوير/Docker يبقى مفتوحاً — وثّق ذلك على الأقل).

### 🔴 SEC-3: CORS: `allow_origins=["*"]` مع `allow_credentials=True`

- **المكان:** `backend/app/main.py:90-97`.
- **المشكلة:** هذا المزيج يجعل Starlette يعكس أي Origin مع السماح بالاعتمادات — أوسع سياسة ممكنة. لا توجد اعتمادات حالياً (لا كوكيز ولا جلسات)، لكنها قنبلة موقوتة: أول ميزة مصادقة تُضاف ستكون مكشوفة لأي موقع.
- **الحل:** `allow_credentials=False`، وقصر `allow_origins` على قائمة معروفة (`http://localhost:3000` + نطاق Pages) عبر إعداد في `Settings`.

### 🟠 SEC-4: روابط غير معقّمة في الواجهة — XSS عبر `javascript:` URI

- **المكان:** `frontend/src/components/NewsFeed/NewsFeed.jsx:96`، `frontend/src/components/Iran/IranPanel.jsx:156,177,227`.
- **المشكلة:** `href={event.url}` و`href={strike.video_url}` تُمرَّر مباشرة من بيانات خلاصات RSS خارجية. `RasadMap.jsx` يعقّم بـ `safeUrl()` لكن هذه المكونات لا تفعل. خلاصة خبيثة (أو مخترقة — nitter mirrors مثلاً) تستطيع وضع `javascript:...` في حقل الرابط، فينفَّذ عند نقر المستخدم.
- **التأثير:** تنفيذ سكربت في سياق التطبيق (وفي نسخة سطح المكتب: داخل أصل `127.0.0.1:8000` نفسه الذي يخدم API).
- **الحل:** انقل `safeUrl` من `RasadMap.jsx` إلى `utils/constants.js` (أو ملف `utils/security.js`) واستخدمها في **كل** موضع `href` يعرض بيانات خارجية:
  ```jsx
  import { safeUrl } from '../../utils/security';
  {safeUrl(event.url) && (
    <a href={safeUrl(event.url)} target="_blank" rel="noopener noreferrer">…</a>
  )}
  ```

### 🟠 SEC-5: نوافذ الخريطة للمنشآت/القواعد/الأنابيب بلا تهريب HTML

- **المكان:** `RasadMap.jsx` — طبقات nuclear (السطر ~305-344)، bases (~363-373)، pipelines (~389-399)، وكذلك `RasadGlobe.jsx` للتسميات المقابلة.
- **المشكلة:** `fac.notes`، `b.notes`، `p.name_ar`… تُحقن في `innerHTML` بدون `esc()`. البيانات حالياً من JSON محلي ثابت (خطر منخفض)، لكن القالب مطابق تماماً لقالب الأحداث الخارجية — أول من يحوّل هذه البيانات لمصدر خارجي (API تحديثات مثلاً) يرث XSS جاهزاً.
- **الحل:** طبّق `esc()` بشكل موحّد على كل القيم النصية في كل القوالب، بغضّ النظر عن مصدرها. القاعدة: «كل ما يدخل innerHTML يُهرَّب».

### 🟡 SEC-6: `Event.title.contains(search)` — حقن أحرف LIKE

- **المكان:** `backend/app/api/events.py:43-45`.
- **المشكلة:** لا يوجد حقن SQL (الاستعلام مُعامل)، لكن `%` و`_` من المستخدم تعمل كأحرف بدل في LIKE — نتائج غير متوقعة وأداء أسوأ. مشكلة صغيرة لكنها مجانية الإصلاح بتهريب `%`/`_` أو استخدام `func.instr`.

## 2. أخطاء برمجية ومنطقية

### 🐛 BUG-1: GDELT يخزّن التاريخ في حقل الوصف

- **المكان:** `backend/app/collectors/gdelt.py:108` — `description=article.get("seendate", "")`.
- **المشكلة:** حقل `description` لكل أحداث GDELT يحتوي طابعاً زمنياً مثل `20260720T110000Z` بدل وصف. الواجهة تعرضه للمستخدم في تفاصيل الحدث ونوافذ الخريطة.
- **الحل:** GDELT artlist لا يعيد وصفاً — استخدم `description=""` أو ادمج `domain` كمصدر، ولا تعرض حقلاً فارغاً في الواجهة.

### 🐛 BUG-2: أزرار المدة في الخط الزمني لا تعمل (UI ميت)

- **المكان:** `frontend/src/components/Timeline/Timeline.jsx:9,38-44`.
- **المشكلة:** حالة `hoursBack` تتغير بالضغط على أزرار (6/12/24/48 ساعة) لكنها **لا تُستخدم في أي فلترة** — الأزرار تغيّر لونها فقط والقائمة لا تتغير. المستخدم يظن أنه يفلتر وهو لا يفعل.
- **الحل:** إما فلترة فعلية: `list = list.filter(e => new Date(e.event_date) > Date.now() - hoursBack*3600e3)` داخل `useMemo`، أو حذف الأزرار.

### 🐛 BUG-3: مؤشر «متصل» في الترويسة ثابت دائماً

- **المكان:** `frontend/src/App.jsx:137` — `isConnected={true}`، و`usePolling` يبتلع الأخطاء (`error` لا يُستهلك في أي مكان).
- **المشكلة:** في لوحة مراقبة استخباراتية، أخطر حالة هي «بيانات قديمة تبدو حية». لو سقط الـ Backend تظل الواجهة تعرض «متصل 🟢» وآخر بيانات ناجحة إلى الأبد.
- **الحل:** مرّر حالة الخطأ الفعلية:
  ```jsx
  const { data: stats, error: statsError, refetch: refetchStats } = usePolling(...);
  <Header isConnected={!statsError} ... />
  ```
  والأفضل: أظهر بانر «تعذّر الاتصال — البيانات المعروضة من HH:MM» عند فشل أي polling رئيسي.

### 🐛 BUG-4: healthcheck في docker-compose يفشل دائماً

- **المكان:** `docker-compose.yml` (backend healthcheck: `curl -f …`) مقابل `backend/Dockerfile` (`python:3.12-slim`).
- **المشكلة:** صورة `python:3.12-slim` لا تحتوي `curl` — الفحص يفشل دائماً والحاوية تُعلَّم `unhealthy` مهما كانت سليمة. أي أتمتة تعتمد على الحالة (restart policies, depends_on: condition) ستتصرف خطأ.
- **الحل:** استبدل curl بأداة موجودة:
  ```yaml
  test: ["CMD", "python", "-c", "import urllib.request; urllib.request.urlopen('http://localhost:8000/api/health')"]
  ```

### 🐛 BUG-5: سباق «تحقّق ثم أدرج» يُسقط دفعات كاملة

- **المكان:** كل الجامعين (`gdelt.py`, `news_api.py`, `rss_feeds.py`, `iran_osint.py`) — نمط `SELECT ... WHERE source_id = X` ثم `session.add`، مع `commit()` واحد في نهاية الدفعة.
- **المشكلة:** `source_id` عليه قيد `unique`. إذا تزامن جامعان على نفس المقال (مثلاً: `POST /api/refresh` يدوي أثناء عمل المجدول — `max_instances=1` يحمي داخل الوظيفة الواحدة فقط، لا بين المجدول والـ API)، ينجح فحص الوجود لكلَيهما ثم يفشل `commit()` الثاني بـ IntegrityError — **فتضيع الدفعة كلها** لأن الالتزام واحد في النهاية. التعليق في `scheduler.py:67-69` يعترف بالمشكلة ويتحاشاها بتوقيت التشغيل بدل حلها.
- **الحل:** الأمتن مع SQLite: إدراج متجاهل للتعارض بدل الفحص المسبق:
  ```python
  from sqlalchemy.dialects.sqlite import insert
  stmt = insert(Event).values(**event_dict).on_conflict_do_nothing(index_elements=["source_id"])
  await session.execute(stmt)
  ```
  هذا يلغي أيضاً استعلام SELECT لكل مقال (تحسين أداء مجاني).

## 3. الاعتمادية وإدارة البيانات

### 🔴 REL-1: نمو غير محدود لقاعدة البيانات (أهم مشكلة تشغيلية)

- **المكان:** `backend/app/models/database.py` — جداول `events`، `flight_tracks`، `iranian_leader_news`.
- **المشكلة:** لا توجد أي آلية حذف أو أرشفة. `flight_tracks` وحده يستقبل صفوفاً لكل طائرة عسكرية كل 30 ثانية إلى الأبد (آلاف الصفوف يومياً). خلال أشهر: ملف SQLite بمئات الميغابايت، استعلامات `country-index` (التي تحمّل الأحداث كلها في بايثون) تتباطأ خطياً، والنسخ الاحتياطي يصبح عبئاً. **هذا ما سيكسر المشروع بعد سنة.**
- **الحل:** وظيفة تنظيف مجدولة يومياً:
  ```python
  async def prune_old_data():
      async with get_session_factory()() as s:
          cutoff_events = datetime.now(timezone.utc) - timedelta(days=30)
          cutoff_flights = datetime.now(timezone.utc) - timedelta(days=7)
          await s.execute(delete(Event).where(Event.collected_at < cutoff_events))
          await s.execute(delete(FlightTrack).where(FlightTrack.tracked_at < cutoff_flights))
          await s.execute(delete(IranianLeaderNews).where(IranianLeaderNews.collected_at < cutoff_events))
          await s.commit()
  ```
  مع `VACUUM` دوري أو `PRAGMA auto_vacuum`.

### 🟠 REL-2: SQLite بدون WAL مع كتّاب متزامنين

- **المكان:** `database.py:113` — `create_async_engine(database_url)` بدون أي PRAGMA.
- **المشكلة:** 6 وظائف مجدولة + طلبات API تكتب/تقرأ على نفس ملف SQLite. بدون `journal_mode=WAL` ستظهر أخطاء `database is locked` تحت الحمل، وكل استثناء يُبتلع في `except Exception` فيضيع الجمع بصمت.
- **الحل:**
  ```python
  from sqlalchemy import event
  _engine = create_async_engine(database_url)
  @event.listens_for(_engine.sync_engine, "connect")
  def _set_sqlite_pragma(dbapi_conn, _):
      cur = dbapi_conn.cursor()
      cur.execute("PRAGMA journal_mode=WAL")
      cur.execute("PRAGMA busy_timeout=5000")
      cur.close()
  ```

### 🟠 REL-3: خلاصات ميتة تُفشل نظام الثقة بصمت

- **المكان:** `backend/app/collectors/iran_osint.py:24-88`.

## 6. تجربة المستخدم وإمكانية الوصول

### 🟠 UX-1: الترجمة الإنجليزية غير مكتملة — مزيج لغات في وضع EN

### 🟠 UX-2: إمكانية الوصول (a11y) شبه غائبة

- أحجام خط 8-10px (`text-[8px]`, `text-[9px]`) في كل مكان — دون حد القراءة المريح وغير قابلة للتكبير بسلاسة.
- كل الأزرار الأيقونية (تكبير/تصغير، الجرس، التحديث، طي اللوحة) بلا `aria-label` (بعضها له `title` فقط — لا يكفي لقارئات الشاشة).
- الخطورة تُنقل بالألوان والنقاط الملونة فقط (🔴🟠🟡🟢) — مستخدمو عمى الألوان يفقدون المعلومة الأهم في التطبيق.
- عناصر قابلة للنقر هي `<div onClick>` (بطاقات الأحداث، عناصر التجميع) — لا وصول بلوحة المفاتيح إطلاقاً.
- تباين `text-slate-500` (#64748b) على `#0d1117` مع خط 9px تحت معايير WCAG AA للنص الصغير.
- **الحل:** جولة a11y واحدة: `aria-label` لكل زر أيقوني، `role="button" tabIndex={0}` + مفتاح Enter للبطاقات، رفع الحد الأدنى للخط إلى 11-12px، وإضافة نص/رمز بجانب اللون للخطورة.

### 🟠 UX-3: لا استجابة للشاشات الصغيرة رغم كونه PWA

- **المكان:** `App.jsx:209` (`w-[500px]` ثابتة)، `Header.jsx` (صف واحد مكتظ بـ 8 عناصر).
- **المشكلة:** المشروع يعلن PWA قابلاً للتثبيت على الجوال، لكن اللوحة الجانبية بعرض ثابت 500px والترويسة تنكسر تحت ~1100px. على هاتف: التطبيق غير قابل للاستخدام عملياً.
- **الحل:** نقطة كسر واحدة تكفي كبداية: تحت `lg` اجعل اللوحة درجاً سفلياً بعرض كامل (`fixed bottom-0 h-1/2 w-full`) وقلّص عناصر الترويسة لقائمة.

### 🟡 UX-4: أخطاء الجلب صامتة تماماً — لا toast ولا بانر عند فشل أي API (تكامل مع BUG-3). أضف مؤشر خطأ موحداً.

## 7. DevOps والتغليف وCI/CD

### 🟠 OPS-1: docker-compose «إنتاجي» يشغّل خوادم تطوير

## ماذا سأفعل لو أصبحت المسؤول التقني اليوم؟

**اليوم الأول:** إبطال المفاتيح المسرّبة (لا شيء آخر يهم قبلها)، إضافة LICENSE و`.env.example`، وتفعيل Secret Scanning.

**الأسبوع الأول:** المرحلة الأولى كاملة + إصلاح lint وحذف الكود الميت — أهدف لأن يصبح «الأخضر في CI» يعني شيئاً حقيقياً (lint واجهة + أمن روابط + اختبارات تصنيف).

**الشهر الأول:** توحيد طبقة الجامعين (BaseCollector + processors) لأنها النقطة التي يتضاعف عندها كل تطوير مستقبلي، ثم سياسة الاحتفاظ بالبيانات وWAL، ثم فصل القراءة عن الجمع في flights.

**ما كنت سأعيد تصميمه من الصفر:** طبقة الجمع فقط. البقية (FastAPI + SQLite + React + Leaflet) اختيارات صحيحة تماماً لحجم المشروع وطبيعته — المشكلة ليست في المعمارية الكبرى بل في انضباط التفاصيل: التكرار، الصمت عند الفشل، وغياب حدود النمو.
