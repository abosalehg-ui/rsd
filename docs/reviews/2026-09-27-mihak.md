## 1. نظرة عامة سريعة

**وش يسوي:** رصد لوحة شخصية تجمع أخبار الشرق الأوسط العسكرية/الأمنية/النووية من 7 مصادر (GDELT، NewsAPI، RSS، UCDP، ADS-B، خلاصات OSINT إيرانية، وجامع نووي متخصص + Google News)، تصنّفها بمطابقة كلمات بحدود الكلمة، تحدّد موقعها بمعجم جغرافي (دول/مدن/منشآت)، تجمع الأخبار المتشابهة في «قصص»، تحسب درجة خطر نووي/إشعاعي مفسَّرة لكل خبر ومؤشرًا عامًا، وتعرض كل ذلك على خريطة 2D (Leaflet) أو كرة 3D (globe.gl) مع تنبيهات صوتية وتقرير دوري قابل للتصدير وواجهة ثنائية اللغة RTL/LTR.

**البنية:** باك إند FastAPI بطبقات واضحة (`collectors → processors → models → api + middleware`) على SQLite غير متزامن مع APScheduler، وواجهة React أحادية الصفحة تستطلع الـ API دوريًا. ثلاث طرق نشر: Docker (dev/prod عبر nginx)، GitHub Pages للواجهة، ومثبّت ويندوز (PyInstaller + Inno Setup) أو `Rasad.bat` بنقرة واحدة.

المتبقي ثلاث نقاط:

**(أ) `backend/app/api/nuclear.py` — `nuclear_brief()` يستدعي مسارًا آخر كدالة عادية:**

### 2.5 الأداء واستهلاك الموارد — **7.5/10**

ما تحسّن: `get_collectors_status` صار استعلامين مجمّعين بدل عشرة، `country-index` بـ GROUP BY، مؤشر القصص بفهرس معكوس كلمة→قصة بدل O(n²)، تواقيع المحتوى في الخريطة *والكرة* الآن تمنع إعادة بناء الـ Sprites كل 30 ثانية، `iconSvg` و`countTexture` مخزّنة مؤقتًا، و`ensure-deps.mjs` يمنع انهيار البناء بنسخة three قديمة. المتبقي:

**(أ) `api/events.py::get_stats` = 18 استعلامًا تسلسليًا لكل طلب:** `_escalation()` استعلامان (إجمالي + ساخن)، تُستدعى للفترة الحالية والسابقة و8 شرائح (`_SERIES_BUCKETS`) = 20 استعلامًا، فوق 5 استعلامات التوزيعات. `Cache-Control: max-age=60` يخفّف على العملاء المتعددين لكن كل دقيقة تُعاد. **الحل:** استعلام واحد `GROUP BY strftime('%s', event_date) / bucket_seconds` مع `SUM(CASE WHEN military AND severity IN (...) THEN 1 END)` يعيد الشرائح الثماني والفترتين معًا.

**(ب) `api/nuclear.py::nuclear_brief` يحمّل أحداث الفترة نفسها ثلاث مرات:** `build_risk()` يجلب `current` (حتى 3000 صف)، ثم `nuclear_brief` يجلب `events` بنفس الشرط، ثم `facilities_watch()` يجلبها ثالثةً — وكلها تُسلسَل عبر `collapse` بتكرار 2.3-هـ. **الحل:** اجلب مرة ومرّر القائمة إلى `risk_snapshot` و`_facility_watch`.

**(ج) `scheduler.py` بلا `misfire_grace_time` ولا `coalesce`:** الافتراضي في APScheduler 3 هو ثانية واحدة. حين تنشغل الحلقة (جمع أولي متزامن لسبعة مصادر عند الإقلاع، أو `backfill_analysis` على قاعدة سطح مكتب فيها 30 يومًا) تفوّت وظيفة RSS (كل 120 ثانية) موعدها بأكثر من ثانية فتُسقَط مع تحذير `Run time of job ... was missed`. **الحل:** `scheduler = AsyncIOScheduler(job_defaults={"misfire_grace_time": 60, "coalesce": True})`.

**(د) `get_map_events` ما زال بحدّ ثابت `.limit(200)`** بينما `get_events` يجلب حتى 500 وقائمة الأخبار تطلب 200 قصة (≈ 600 حدث خام). في يوم مزدحم تعرض القائمة أحداثًا لا تظهر على الخريطة بلا تفسير. **الحل:** معامل `limit` كبقية المسارات + طيّ القصص قبل الحدّ.

**الخلاصة بجملة:** المشروع صعد من 7.4 إلى 7.9 لأن خطة الإصلاح السابقة نُفّذت فعلًا لا شكليًا (أمن، CSP، اختبارات، RTL، تصميم)، وطبقة التحليل النووي الجديدة مبنية بعناية وموثّقة. اللي بقي مو هيكلة، بل **ملف واحد** (`iran_osint.py`) نُسي في ترقية المطابقة فيضع براكة الإماراتية في وسط إيران ويُغرق قائمة قائد بأخبار لا تخصّه، وخمس خلاصات مكرّرة تضخّم المؤشرات، وعلَم `stale` يصل الخادم ولا يصل الشاشة.
